# 0004. Бесполость персонажа — гендер выбирает пользователь

- **Status:** accepted
- **Date:** 2026-05-19
- **Deciders:** @vadimkolobanov

## Контекст

Капля — абстрактная форма. Назначать ей пол на уровне дизайна — значит сузить аудиторию и встрять в культурные срачи. Но в русском (и многих других языках) местоимения нужны для LLM-промптов и UI.

## Рассмотренные варианты

1. **Жёстко мужской / женский по дефолту** — отказ: сегментирует аудиторию.
2. **Случайный гендер при рождении** — отказ: рандом без агентности воспринимается как «навязанный».
3. **Бесполое существо, пользователь выбирает местоимение при имянаречении** — выбран.

## Решение

**Капля — бесполое существо.** На шаге онбординга «имянаречение» пользователь выбирает:

- местоимение (он / она / они / оно)
- имя

Выбор местоимения:
- сохраняется в Room
- передаётся в LLM system prompt как обязательное поле
- управляет всеми UI-строками через `pluralStringResource`/`stringResource` с заполнением

## Последствия

### Позитивные
- Аудитория не отсекается по гендерному признаку
- Пользователь чувствует агентность с первого касания
- LGBTQ+ friendly без отдельных опций

### Негативные
- Усложняется локализация: каждая строка про каплю — параметризованная
- Lint-проверка на «нет хардкод-местоимений» обязательна

### Что станет сложнее
- LLM prompts: pronoun должен быть в каждом промпте, иначе модель скатывается в дефолт по обучающим данным
- Тестирование: eval-сет должен включать кейсы для каждого местоимения
